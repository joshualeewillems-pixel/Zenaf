# Human–AI symbiosis — guiding principle (direction, not spec)

**Status:** North-star intent and constraints for how Atria may evolve. **Not** a commitment to build everything described here. **Do not** treat this as permission to add invasive capture, hidden modeling, or premature persistence.

---

## System direction — human–AI symbiosis

Atria is evolving toward a human–AI symbiosis layer.

**Long-term direction:**

- The system should be capable of learning from how a user thinks, decides, creates, and acts across domains (creative, practical, relational, etc.).
- This includes low-resolution signals (decisions, traces, patterns) and potentially higher-resolution signals (media, motion, workflows) **only** with explicit user consent.
- The purpose is not surveillance or control, but:
  - amplification of autonomy
  - preservation of intuition
  - learning acceleration
  - meaningful coordination between individuals

**The system may eventually support:**

- reusable “judgment profiles” or advisory styles
- cross-user learning and collaboration
- tools that help individuals operate across multiple contexts more fluidly
- alignment of needs, offerings, and opportunities across a network

---

## Critical principles (must hold at all times)

### 1. User agency is primary

- No hidden modeling
- No silent data capture
- No assumption of identity or traits
- All interpretation must be transparent and revocable

### 2. Consent and scope

- Higher-resolution data (video, motion, behavioral capture, etc.) is **never** assumed
- All data collection must be:
  - explicit
  - scoped
  - understandable
- Default system operates fully without invasive inputs

### 3. Interpretation is always tentative

- The system does not “define the user”
- It offers hypotheses, not labels
- No fixed personality or identity models

### 4. No premature persistence

- Do not store developmental interpretations as stable truth
- Only persist data when it is:
  - intentional
  - reviewable
  - versioned
  - justified by clear product value

### 5. Build from low-resolution to high-resolution

- Start with:
  - signals
  - decisions
  - traces
- Only expand resolution when:
  - the system proves value
  - the user opts in

---

## Current product reality

**Right now, Atria is:**

- a decision and interpretation environment
- a system that helps users:
  - clarify thinking
  - organize execution
  - reflect on patterns

**It is not yet:**

- a full behavioral recording system
- a profile marketplace
- a global coordination layer

**Do not build those systems prematurely.**

---

## Development guideline

When making changes:

- prefer improving clarity, coherence, and usability of existing flows
- avoid introducing new systems that assume long-term vision is already implemented
- keep the system lightweight, inspectable, and grounded

**Every feature should answer:** “Does this help the user think, decide, or act better right now?”

---

## Future compatibility (important)

Design current structures so they can **later** support:

- versioned judgment artifacts
- evidence-linked patterns
- opt-in higher-resolution data

**Do not implement those systems yet.**

---

## Summary

Atria is moving toward a symbiotic learning system. **But today** it must remain simple, user-trust-first, non-invasive, and grounded in real, immediate usefulness.

**Do not sacrifice present clarity for future vision.**
